❯ does windows keep track of when a .exe was last launched?                     

● Yes, Windows maintains several records of execution history, though none are
  designed as a clean API:

  Most useful:
  - Prefetch (C:\Windows\Prefetch\*.pf) — stores the last 8 run timestamps per
  executable (Windows 8+), plus run count. File name encodes the exe name and a
  path hash. Readable but requires parsing a binary format.
  - UserAssist
  (HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist) —
  registry key with ROT13-encoded program paths, last run timestamp, and run
  count. Only covers apps launched via Explorer/shell (Start menu, desktop
  shortcuts, file associations) — not direct process spawns.

  Less reliable:
  - AmCache (C:\Windows\AppCompat\Programs\Amcache.hve) — tracks first execution
   time and file metadata, not last run.
  - ShimCache / AppCompatCache — tracks which exes have run but the timestamp is
   the file's last-modified time, not execution time.
  - Event Log (Event ID 4688) — process creation events, but process auditing is
   off by default.

  Practical takeaway for this project: Prefetch is the most promising — it has
  actual last-run timestamps and is updated regardless of how the process was
  launched. The catch is the binary format (you'd need the .NET NativeBridge to
  parse it, or a library), and Prefetch can be disabled by users/admins.
  UserAssist is easier to read (it's just a registry value) but misses games
  launched directly.

  If you want to retroactively seed lastPlayedAt for games that were run outside
   the launcher, Prefetch is the place to look.
